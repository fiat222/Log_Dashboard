OTel Agent — Multi-VM Setup Guide
===================================

Purpose: collect Docker container logs from any VM and forward to the
central OTel Gateway on the log-dashboard server (10.135.4.67).

Architecture
------------
  [VM with containers]
    └── otel-agent (filelog receiver)
          └── gRPC → otel-gateway:4317 (main server)
                └── ClickHouse → observability.otel_logs_local

Prerequisites
-------------
- Docker + Docker Compose installed on target VM
- Port 4317 open on main server (add to otel-gateway service in main docker-compose.yml):
    ports:
      - "4317:4317"

Deploy on a new VM
------------------
1. Copy this Chores/OTel/ directory to the target VM:
     scp -r Chores/OTel/ user@target-vm:/opt/otel-agent/

2. Edit agent-config.yaml on the target VM:
   - Change gateway endpoint if different from 10.135.4.67:4317
   - Add containers to exclude in filter/exclude_containers (see below)

3. Start the agent:
     cd /opt/otel-agent
     docker compose up -d

4. Verify logs flowing (wait ~30s):
     docker compose logs -f otel-agent    # should show no errors

5. Check ClickHouse on main server:
     SELECT HostName, count() FROM observability.otel_logs_local
     WHERE HostName = '<target-vm-hostname>'
     GROUP BY HostName


Exclude specific containers
----------------------------
Edit filter/exclude_containers in agent-config.yaml:

  Option A — exact names (strict match):
    filter/exclude_containers:
      logs:
        exclude:
          match_type: strict
          resource_attributes:
            - key: container.name
              value: my-noisy-container
            - key: container.name
              value: another-container

  Option B — regex pattern (recommended for multiple):
    filter/exclude_containers:
      logs:
        exclude:
          match_type: regexp
          resource_attributes:
            - key: container.name
              value: "^(prometheus|grafana|cadvisor|node-exporter|traefik|my-container)$"

After editing config, restart agent:
     docker compose restart otel-agent

To disable exclusion entirely (collect everything):
  Remove "filter/exclude_containers" from the pipeline processors list
  under service.pipelines.logs.processors — do NOT delete the filter block itself,
  just remove it from the list. Easy to re-add without reconfiguring.


Temporarily re-enable DEBUG logs
----------------------------------
Remove "filter/drop_debug" from service.pipelines.logs.processors list,
then restart:
     docker compose restart otel-agent

Revert: add "filter/drop_debug" back to the processors list and restart.


Checkpoint / resume
--------------------
The volume "otel_agent_checkpoint" persists the filelog read position.
If the container restarts, it resumes from where it left off — no duplicate logs.
To reset and re-read from beginning: remove the volume (use sparingly):
     docker compose down -v && docker compose up -d


Log volume expectations
-----------------------
Containers that log mostly at DEBUG level (grafana, prometheus, node-exporter, gatus,
uptime-kuma) will produce few or no rows in ClickHouse because filter/drop_debug removes
DEBUG entries. This is normal — not a pipeline fault.

To confirm a container's logs exist on disk:
     sudo tail -5 /var/lib/docker/containers/$(docker inspect <name> --format "{{.Id}}")/$(docker inspect <name> --format "{{.Id}}")-json.log

Application stdout buffering
-----------------------------
Apps that buffer stdout (Python, Java) write to Docker's json-file in batches, not per
line. OTel sees the delay. Nginx access logs are unbuffered — realtime.
Fix for Python containers (add to their docker-compose.yml, no code change needed):
     environment:
       - PYTHONUNBUFFERED=1


Verify agent health
-------------------
     docker compose exec otel-agent wget -qO- http://localhost:13133/    # health check
     docker stats otel-agent    # memory should stay under 256 MiB limit


Files
-----
  agent-config.yaml   — OTel collector config (edit gateway endpoint + exclusions)
  docker-compose.yml  — standalone compose for agent-only deployment
  instruction.txt     — this file
